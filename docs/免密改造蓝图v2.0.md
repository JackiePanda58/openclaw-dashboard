## 1. 架构纠正：身份 Mock 注入方案

### 1.1 原方案问题分析

原方案"直接移除 session"是 P0 级逻辑错误，原因：

- **数据库强依赖 User_ID**：会话数据存储路径 `~/.openclaw/agents/main/sessions/{sessionId}.jsonl` 包含会话标识
- **认证层与业务层耦合**：`isAuthenticated()` 和 `requireAuth()` 中间件在每个 API 调用前执行
- **历史数据关联**：sessions.json 中存储 username 与会话的映射关系

### 1.2 身份 Mock 注入架构

采用"欺骗数据库"方案，在中间件层强行注入 Mock 用户身份：

```
┌─────────────────────────────────────────────────────────────────────┐
│                        请求入口 (HTTPS)                              │
└─────────────────────────────────────────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────────┐
│                  AuthMiddleware (认证中间件)                         │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │  if (DISABLE_AUTH === true) {                                │   │
│  │    // 免密模式：强行注入 Mock 身份                           │   │
│  │    req.user = {                                               │   │
│  │      id: 'local_admin',                                      │   │
│  │      username: 'admin',                                      │   │
│  │      role: 'root',                                           │   │
│  │      auth_source: 'mock_injection',                          │   │
│  │      auth_time: Date.now()                                   │   │
│  │    };                                                        │   │
│  │    return next(); // 跳过 session 验证                      │   │
│  │  }                                                           │   │
│  │  // 正常模式：验证 session                                    │   │
│  │  return requireAuth(req, res);                               │   │
│  └─────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────┘
                                 │
                                 ▼
┌─────────────────────────────────────────────────────────────────────┐
│                    业务逻辑层 (Mock User 已注入)                      │
│  // 所有 API 正常执行，req.user 携带 Mock 身份                        │
│  // 数据库操作使用 local_admin 作为 user_id                         │
└─────────────────────────────────────────────────────────────────────┘
```

### 1.3 核心代码实现

```javascript
// server.js - 认证中间件改造

// 免密开关 (可通过环境变量或配置文件控制)
const DISABLE_AUTH = process.env.DISABLE_AUTH === 'true';

// Mock 身份注入器
function authMiddleware(req, res, next) {
  // 免密模式：直接注入 Mock 身份
  if (DISABLE_AUTH) {
    req.user = {
      id: 'local_admin',
      username: 'admin',
      role: 'root',
      email: 'admin@local',
      auth_source: 'mock_injection',
      auth_time: Date.now(),
     免密模式: true
    };
    console.log('[AUTH] Mock身份注入:', req.user);
    return next();
  }
  
  // 正常模式：走原有 session 验证
  if (!requireAuth(req, res)) {
    return; // requireAuth 已处理 401 响应
  }
  
  // 从 session 中提取用户信息
  const token = extractToken(req);
  const session = sessions.get(token);
  if (session) {
    req.user = {
      id: session.username,  // 使用 session 中的 username 作为 id
      username: session.username,
      role: session.role || 'user',
      auth_source: 'session'
    };
  }
  
  return next();
}
```

## 2. 腾讯级 API 契约协议

### 2.1 免密状态 Request Header 定义

当 `DISABLE_AUTH=true` 时，调用 `/api/agents` 等接口需要模拟以下 Header：

| Header 字段 | 必须 | 值示例 | 说明 |
|------------|------|--------|------|
| X-User-ID | ✅ | `local_admin` | 替代 Authorization 的用户标识 |
| X-User-Role | ✅ | `root` | 用户角色 |
| X-User-Name | ✅ | `admin` | 用户名 |
| X-Auth-Source | ✅ | `mock_injection` | 认证来源标识 |
| X-Auth-Time | ✅ | `1742059200000` | 认证时间戳(毫秒) |

**完整请求示例**：

```bash
curl -X GET "https://www.openpanda.fun/api/agents" \
  -H "X-User-ID: local_admin" \
  -H "X-User-Role: root" \
  -H "X-User-Name: admin" \
  -H "X-Auth-Source: mock_injection" \
  -H "X-Auth-Time: 1742059200000"
```

### 2.2 异常流处理

| 场景 | HTTP Status Code | Response Body |
|------|-----------------|----------------|
| Mock 注入成功 | `200` | 正常业务数据 |
| Mock 注入失败 (系统错误) | `500` | `{ "error": "Auth injection failed", "code": "MOCK_INJECT_ERROR" }` |
| Mock 身份验证失败 | `403` | `{ "error": "Mock identity invalid", "code": "MOCK_ID_INVALID" }` |
| 免密开关未开启但无 token | `401` | `{ "error": "Unauthorized", "code": "NO_TOKEN" }` |
| Session 已过期 | `401` | `{ "error": "Session expired", "code": "SESSION_EXPIRED" }` |

### 2.3 响应数据结构

```json
{
  "success": true,
  "data": { ... },
  "meta": {
    "auth_mode": "mock_injection",
    "user": {
      "id": "local_admin",
      "role": "root"
    },
    "timestamp": "2026-03-14T22:00:00Z"
  }
}
```

## 3. 影响面评估矩阵

### 3.1 数据隔离影响分析

| 维度 | 风险评估 | 缓解措施 |
|------|---------|---------|
| **Chat 记录混乱** | ⚠️ 中风险 | 所有免密用户共享 `local_admin` 会话，但每个浏览器标签页生成独立 `sessionId`（UUID），存储在不同 .jsonl 文件中，不会混淆 |
| **会话标签混淆** | ✅ 低风险 | 使用 sessionId 作为唯一标识，sessionId 格式: `{uuid}.jsonl`，每个标签页独立 |
| **消息归属** | ✅ 低风险 | .jsonl 文件中每条消息包含 `timestamp` 和 `role` 字段，可追溯来源 |
| **Cost 统计** | ✅ 低风险 | 每个 sessionId 独立计算 cost，不跨会话累计 |

**结论**：虽然所有免密用户共享 `admin` 用户名，但底层存储以 UUID sessionId 隔离，**历史 Chat 记录不会混乱**。

### 3.2 持久化影响分析

| 数据类型 | 存储路径 | 用户标识 | 影响 |
|---------|---------|---------|------|
| 会话消息 | `~/.openclaw/agents/main/sessions/{uuid}.jsonl` | sessionId (UUID) | ✅ 独立隔离 |
| 会话元数据 | `~/.openclaw/agents/main/sessions/sessions.json` | sessionId (UUID) | ✅ 独立隔离 |
| Cost 统计 | 内存 + sessionCostCache | sessionId | ✅ 独立隔离 |
| Live Events | 内存广播 | sessionId | ✅ 独立隔离 |

**新的 local_admin 产生的数据**：
- 存储分区：`~/.openclaw/agents/main/sessions/`
- 文件命名：仍使用 UUID（由浏览器标签页生成），不受 `local_admin` 影响
- **存储位置不变**，无需调整分区策略

### 4.3 灰度与回退方案

#### 4.3.1 应急开关设计

```javascript
// 环境变量控制 (推荐)
process.env.DISABLE_AUTH = 'true' | 'false'

// 或配置文件控制 (~/.openclaw/config.json)
{
  "security": {
    "disable_auth": false,  // 默认关闭
    "allowed_ips": ["127.0.0.1", "10.0.0.0/8"],  // 白名单 IP
    "admin_override": true   // 管理员 bypass
  }
}
```

#### 4.3.2 一键回退操作

```bash
# 方式1: 环境变量回退
export DISABLE_AUTH=false
systemctl restart openclaw-dashboard

# 方式2: 配置文件回退
sed -i 's/"disable_auth": true/"disable_auth": false/' ~/.openclaw/config.json
systemctl restart openclaw-dashboard

# 方式3: 如果是 Docker
docker exec -it openclaw-dashboard env DISABLE_AUTH=false
docker restart openclaw-dashboard
```

#### 4.3.3 灰度策略

| 阶段 | 策略 | 验证点 |
|------|------|--------|
| **Stage 1: 内网** | `DISABLE_AUTH=true`，仅限 `127.0.0.1` 访问 | 确认所有 API 正常 |
| **Stage 2: IP 白名单** | 开启 `allowed_ips`，仅限办公网络 IP | 确认员工可正常访问 |
| **Stage 3: 全量** | 移除 IP 限制，公网开放 | 监控异常流量 |
| **Stage 4: 监控** | 开启审计日志，观察 3 天 | 确认无安全事件 |

#### 4.3.4 自动告警

```javascript
// 免密模式异常监控
setInterval(() => {
  if (DISABLE_AUTH) {
    const failedAuth = metrics.get('auth_failed') || 0;
    if (failedAuth > 100) {
      sendAlert('免密模式异常：认证失败次数超过阈值');
    }
  }
}, 60000); // 每分钟检查
```
